工作记录

1. Hexo + Butterfly 博客安装

帮sev在 ~/blog/ 全新安装 Hexo 博客，完整走了从零到跑起来的全流程。解决了三个坑：

① hexo-cli 找不到项目
hexo g 只显示 help 信息，不识别 generate 命令。根因：package.json 缺少 "hexo": {...} 字段，导致 hexo-cli 的 find_pkg() 往上遍历时找不到有效项目。
解决：在 package.json 加 "hexo": { "version": "8.1.2" }。

② Butterfly 主题 YAML 缩进错误
_config.butterfly.yml 里 aplayer:（前面少了空格）导致 js-yaml 解析崩溃，报错指向 mathjax 但真正问题在 aplayer 行。
用 sed -n '44,52p' file.yml | od -c 看字符确认缩进，Python yaml.safe_load() 验证。

③ npm 全局安装权限问题
sudo 需要密码，改用项目本地安装：cd ~/blog && npm install hexo-cli，通过 ./node_modules/.bin/hexo g 调用。

最终：成功生成 17 个静态文件，Butterfly 主题跑通。

2. 桌面宠物 brain 彻底修复

desktop_pet.py 之前一直报 cannot import name 'agent_runner_loop' from 'agent_loop'。原因分析：

  • agentmain.py 依赖完整的旧版 GenericAgent（需要 llmcore、ga、handler 等整套模块）
  • 实际可用的只有轻量级 GeneraticAgentLoop（在 agent_loop.py 里，只有对话轮询逻辑）

修复步骤：

  1. 把 from agentmain import GeneraticAgent 改成 from agent_loop import GeneraticAgentLoop
  2. 从 ~/Desktop/ip/GenericAgent/key.txt 读取 MiniMax API key
  3. 在 import sys, os, threading, queue, re, subprocess, json 加上 import time
  4. GeneraticAgentLoop 在独立 daemon 线程里运行，不阻塞 PyQt 事件循环
  5. 修复 SyntaxError：key_file.read_text().strip().split('\n')[0] 断行导致 unterminated string

修复后：nohup python3 ~/.openclaw/workspace/desktop_pet.py & 启动成功，PID 22322，左上角（60, 400）位置。

技术笔记

Hexo CLI 项目识别机制

hexo-cli 的 find_pkg() 往上遍历目录找 package.json，必须有 hexo 字段才认定为有效项目。没有这个字段，hexo CLI 只识别为普通 npm 项目，所以 hexo g 命令不被识别。

YAML 缩进检测

# 看字符的八进制，确认是空格还是 tab
sed -n '44,52p' file.yml | od -c

# Python 快速验证
python3 -c "import yaml; yaml.safe_load(open('file.yml'))"

GeneraticAgentLoop vs agentmain

轻量对话循环，不需要完整 GA 环境。初始化只需 API key：

from agent_loop import GeneraticAgentLoop
agent = GeneraticAgentLoop(api_key)
threading.Thread(target=agent.run, daemon=True).start()

MCP Server JSON-RPC over stdio

Python subprocess 的 subprocess.PIPE 配合 JSON-RPC 2.0：

  • 请求序列化为 JSON 写入 stdin
  • 响应从 stdout 读
  • 超过 30s 超时则会话断开
