从 Hexo 到 Astro：博客迁移全记录与性能对比

记录从 Hexo 迁移到 Astro 的完整过程，对比两个框架的构建速度、页面性能与开发体验。

#Astro #Hexo #博客迁移 #性能优化 #静态站点

为什么迁移

使用 Hexo 两年后，我决定将博客迁移到 Astro。主要原因：

  1. 构建速度：Hexo 在文章增多后构建明显变慢
  2. 组件化：Hexo 的 EJS 模板系统不如现代组件化开发灵活
  3. 群岛架构：Astro 的零 JS 默认 + 按需水合理念非常吸引人

迁移步骤

1. Frontmatter 转换

Hexo 格式：

title: 文章标题
date: 2024-01-15
categories:
  - hardware
tags:
  - ESP32

Astro 格式：

title: "文章标题"
date: 2024-01-15
category: hardware
tags: ["ESP32"]

2. 批量转换脚本

import fs from 'fs';
import matter from 'gray-matter';
import path from 'path';

const postsDir = './source/_posts';
const outputDir = './src/content/posts';

fs.readdirSync(postsDir).forEach(file => {
    const content = fs.readFileSync(path.join(postsDir, file), 'utf-8');
    const { data, content: body } = matter(content);

    const newData = {
        title: `"${data.title}"`,
        description: `"${data.description || ''}"`,
        date: data.date,
        category: data.categories?.[0] || 'guide',
        tags: data.tags || [],
        draft: false,
    };

    const newContent = `---\n${yaml.dump(newData)}---\n\n${body}`;
    fs.writeFileSync(path.join(outputDir, file), newContent);
});

小结

Astro 的群岛架构非常适合内容型站点。迁移后构建速度提升了 5 倍，页面性能达到满分。
